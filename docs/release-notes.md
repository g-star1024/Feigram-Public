## 版本 2.1.3

### 修复

- **首次登录 100% 失败（`native account is not prepared`）**：`POST /api/auth/start`（登录弹窗「发送验证码」）由 Node 生成全新 `accountId` 后直发 Go，而 Go 侧 `startNativeLogin` 要求该账号记录已存在——全新账号永远没有记录，导致**所有**首次登录必失败；扫码登录（`/api/auth/qr/start`）同样命中。2.1.2 及之前版本全部受影响。

  - **为何此前未被发现**：E2E 脚本预先 `POST /api/native/accounts` 建过档，判据盲区掩盖了首次登录路径。
- **验证**：新增 3 条建档单元测试；真实二进制 E2E（全新数据目录、零预建档案）6/6 全绿——缺凭据明确报错、全新账号走到网络层并返回 40s 超时 + 代理诊断提示、记录自动落盘含手机号与 apiId。

## 版本 2.1.2

### 新增

- **网络代理支持（原生模式）**：此前 Go 侧 MTProto 链路**完全没有代理能力**（`telegram.NewClient` 默认用 `dcs.DefaultResolver()` 裸直连），因此在不能直连 Telegram 的网络里，原生模式必然表现为「登录一直失败 / 转圈」。现在提供三层配置：
  1. **应用内设置（推荐）**：「设置 → 网络代理」填写 `socks5://` / `socks5h://` / `http://` / `https://` 代理，改完立即生效，无需重启。
  2. **环境变量兜底**：`FEIGRAM_PROXY_URL` > `ALL_PROXY` / `all_proxy` > `SOCKS5` / `socks5` > `HTTPS_PROXY` / `https_proxy` > `HTTP_PROXY` / `http_proxy`。
  3. **直连**：两者都没有时按原行为直连。
- **优先级与生效范围**：应用内设置 > 环境变量 > 直连。MTProto 建连（登录、健康检查、会话、下载）与媒体 HTTP 传输都会走代理。
- **回环豁免**：媒体传输对指向本机的回环地址强制直连，避免用户配了远端代理后打断本机网关 / sidecar 调用。

### 修复

- **代理配置错误不再静默直连**：空主机名、非法协议（如 `socks4`）、非法端口、带路径的地址都会被显式标记为 `invalid` 并在设置页与 `/health` 中报出原因，不再「悄悄退回直连」让用户以为代理生效了。
- **代理不可达时给出可操作提示**：未配代理时提示去「设置 → 网络代理」配置；已配代理仍连不上时提示检查代理进程、核对地址端口、确认代理允许 TCP 直通 Telegram。提示会出现在登录失败与诊断信息中。
- **代理凭据不进日志**：日志与接口只输出 `scheme://host:port`，代理用户名密码一律脱敏。
- **加固登录流程（本次核证中发现的连带缺陷）**：
  - **同一账号重复点登录**：旧流程现在会被取消。此前每次点击都会新起一个 goroutine，两边并行拨号，且旧流程收尾时会把账号状态覆盖成失败。
  - **发起登录超时**：等待验证码上限（40s）到达后立即取消该流程。此前前端早已超时（拿不到 `loginId`，流程在客户端失去意义），服务器端 goroutine 却会继续对 Telegram DC 反复重试。
  - **代理配置变更**：在途登录会被取消。在途登录把旧 dialer 固定在 gotd client 里，不取消就会继续对旧代理拨号重试。
  - **登录流程生命周期**：新增 10 分钟上限，`a.logins` 在流程结束时即摘除，避免登记表随无人轮询的流程堆积。

### 验证

- Go 单元测试：进程内 SOCKS5 / HTTP CONNECT 代理桩，覆盖隧道连通、凭据透传、错误凭据失败、代理拒绝、协议/主机名校验、脱敏、优先级链、回环豁免、gotd 接线（断言 `Resolver` 确实被注入的 dialer 调用）。
- 端到端核证（真实二进制 + 常驻代理桩）：断言代理桩**确实收到指向 Telegram DC 的 CONNECT**，而非仅看接口返回 200。覆盖：环境变量生效、应用内设置覆盖环境变量且旧代理停用、非法地址显式报错、不可达时的提示文案、代理变更后在途登录被取消。

## 版本 2.0.46

### 重要变更（需要部分用户操作）

- **彻底移除 Node 侧 GramJS（`telegram` npm 包）客户端**，Feigram 现在只通过 Go 原生 MTProto（gotd）单客户端连接 Telegram，架构更简单、资源占用更低，也消除了同一账号双端同时握手导致 `AUTH_KEY_DUPLICATED` 的问题。
- **旧版（gramjs 模式）账号将不再可用**：升级后这些账号会显示「需重新登录以升级到原生模式」。请删除该账号后重新登录一次即可转为原生模式；此过程**不会销毁你的 Telegram 账号数据**，云端聊天与媒体不受影响，仅本应用的会话需要重建。
- 已迁移到原生模式（native）的账号不受任何影响，聊天、搜索、媒体播放/下载、后台缓存等能力全部经 Go 原生链路提供。

### 调整

- Node 服务端删除约 2000 行遗留 GramJS 代码路径；登录流程此前已全部改由 Go Telegram Core 处理，本次变更对原生账号的 API 行为无影响。
- 会话保存方式变更：登录后不再保存 Node 侧加密 session，session 由 Go 侧独占管理。
